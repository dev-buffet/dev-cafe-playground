## 活動簡介

大型語言模型越來越強，但有個共通的限制：記不住太多東西。Context window 有上限，塞得太滿反而變成雜訊，而 fine-tune 的成本又不是每個團隊都負擔得起。於是問題變成——在不改動模型的前提下，還能讓 Agent 越用越聰明嗎？

Rei 從三篇論文整理出一個共同答案：把記憶管理好。從外部知識的壓縮（Chain of Summaries）、對話歷史的保留（Recursively Summarizing），到搜尋策略的自我演化，這是一條不需要 fine-tune、也能讓 AI 持續進化的路。

## 主題內容

本次分享深入探討了如何在不進行模型 fine-tune 的情況下，透過優化記憶管理，讓 AI Agent 持續學習與進化。講者 Rei 提出並詳細闡述了三個關鍵方法，為資源有限或不希望頻繁改動模型架構的開發者提供了可行路徑。

### Chain of Summaries：文章知識的壓縮與強化

大型語言模型在處理過長文章時，容易遺漏重點或被雜訊干擾。Chain of Summaries（CoS）方法旨在解決此問題，它讓 Agent 以迭代、自我檢討的方式來壓縮外部文章知識，確保重要資訊被有效保留。

CoS 的運作方式類似黑格爾的辯證法：
1.  **產生初始摘要（Thesis）**：首先由 Agent 根據原始文章生成一份初步摘要。
2.  **自動提問（Antithesis）**：Agent 接著會自我提問，找出初始摘要中未能涵蓋或回答不出的盲點。
3.  **補強摘要（Synthesis）**：根據這些問題，Agent 會回頭檢視原文並補強摘要，使其更加完整與精確。

這個過程會重複多輪，每次都聚焦於一個問題，避免偏誤，最終使摘要比原文更能有效回答問題，大幅節省 token 的同時，提升了資訊擷取的準確率。這就像撰寫旅遊心得後，透過朋友的提問來補足內容，讓心得更加豐富完整。

### Recursively Summarizing：對話歷史的滾動更新

在人機對話中，隨著對話輪次增加，AI Agent 很容易忘記早期對話的內容。Recursively Summarizing（RS）方法便是為了解決這個問題，它讓 Agent 的記憶能夠隨著對話進程「滾動更新」。

RS 的核心機制並非簡單地附加新的對話內容，而是將現有記憶摘要與新的對話進行「融合重寫」。這意味著：
*   **融合重寫**：將新資訊與舊記憶融合成一份新的摘要版本。
*   **細節淡化**：過時或不再重要的細節會自然淡化，而關鍵資訊則被保留。

這種方法僅依賴於 prompting 技術，無需 fine-tune 模型。它確保 Agent 始終保留對話的最新狀態和重要脈絡，就像我們記憶一個朋友近況時，腦中只有「他最近怎麼樣」的印象，每次交流後會將新消息融入並更新，而非逐字記錄每一句話。

### EvolveMem：搜尋策略的自我進化

面對不同類型的問題（例如：事實查詢、語意查詢、時序查詢），單一固定的記憶搜尋策略往往無法有效應對。EvolveMem 提出讓 Agent 具備自我診斷並優化搜尋策略的能力。

EvolveMem 採用了「診斷、提議、評估、守護」的迭代循環：
1.  **評估（Evaluate）**：Agent 針對測試問題執行現有搜尋策略，並計算效能（例如 F1 分數）。
2.  **診斷（Diagnose）**：分析搜尋失敗的原因，找出策略中的缺陷。
3.  **提議（Propose）**：根據診斷結果，Agent 提出新的搜尋策略。
4.  **守護（Guard）**：如果新策略的效能提升，則採用；如果下降，則退回舊策略。

這個過程反覆迭代，Agent 能夠持續優化自身的記憶搜尋機制，使其越來越精準。實測結果顯示，F1 分數在數輪自我演化後有顯著提升。關鍵在於，演化改善的不是「找到更多資訊」，而是「排除會誤導模型的雜訊」，讓 Agent 更有效地聚焦於正確的關鍵記憶。這就像一位經驗豐富的客服主管，不斷調整查詢手冊來更高效地解決客戶問題。

## 結語

在資源有限且不適合頻繁 fine-tune 大型語言模型的現實情境下，透過 Chain of Summaries、Recursively Summarizing 和 EvolveMem 這三種記憶管理方法，可以為 Agent 打造一條持續進化、越用越聰明的可行路徑。這些方法純粹基於 prompting，架構輕量且可以疊加使用，為 AI 的進化提供了高效且彈性的解決方案。
