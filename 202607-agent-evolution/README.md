## 記憶管理：讓 AI Agent 持續進化的三個關鍵
這次分享探討了如何在不進行模型 fine-tune 的情況下，透過優化記憶管理，讓 AI Agent 能夠持續進化並變得更聰明。主要面臨的問題包括：大型語言模型的 Context Window 有限，導致歷史資訊過多時會變成雜訊；資訊量越大反而降低回答品質；以及 fine-tune 需要龐大資料與算力，門檻高。講者 Rei 透過介紹三種核心方法，提出了解決方案，這些方法都圍繞著「管理好記憶」這一核心理念，並且不需要耗費資源去 fine-tune 模型。

### 關鍵一：Chain of Summaries (CoS)
當 Agent 面對過長的文章時，往往難以抓取重點。Chain of Summaries（CoS）的目標是讓摘要過程本身能夠自我優化，找出自己的盲點。其靈感來自黑格爾的辯證法，分為三個步驟：
1.  **產生初始摘要 (Thesis)**：Agent 首先對文章產生一個初步摘要。
2.  **自動提問 (Antithesis)**：Agent 自行判斷這個摘要還遺漏了什麼，自動提出問題。這一步的關鍵在於每一輪只問一個問題，避免因「為了找錯而找錯」導致偏離焦點，同時也要留意 LLM 可能的「自我偏誤」問題。
3.  **補強摘要 (Synthesis)**：根據自動提出的問題，Agent 回到原文中找出更多資訊來補強摘要。
這個過程會重複迭代，直到摘要內容足夠完整。透過這種方法，不僅能將 token 節省 98%，回答準確率也能顯著提升，甚至比直接閱讀原文更能回答問題。概念上類似於寫完旅遊心得後，透過朋友的提問（LLM 自動提問）來不斷補充完善心得內容。

### 關鍵二：Recursively Summarizing (RS)
在長期的對話中，AI Agent 容易忘記早期對話的內容。Recursively Summarizing（RS）旨在讓 Agent 的記憶能夠隨著對話進行「滾動更新」。它不是簡單地附加新資訊，而是將新的對話與現有記憶融合重寫，以確保重要資訊得以保留，而過時的細節則自然淡化。
這個過程可以描述為：
1.  **第一週對話**：產生第一個記憶摘要 v1。
2.  **第二週對話**：將記憶 v1 與第二週的對話融合重寫，產生新的記憶摘要 v2。
3.  **第三週對話**：將記憶 v2 與第三週的對話融合重寫，產生記憶摘要 v3。
這種純 prompting 的方法不需要 fine-tune，就像我們記住一個朋友的近況一樣：腦中只保留一份「他最近怎樣」的印象，每次聊完就將新消息融進去更新，瑣事自然淡忘。這使得 Agent 無需重練大腦，也能持續掌握最新狀態。

### 關鍵三：EvolveMem
不同的問題需要不同的搜尋方法。例如，「體重目標」需要事實查詢（關鍵字搜尋），「為什麼不能跑步」需要語意查詢（語意理解），而「第二週加了什麼訓練」則需要時序查詢（時間感知）。單一固定的搜尋策略無法同時應付所有類型的問題。EvolveMem 讓 Agent 能夠「自我診斷、自我改進搜尋策略」，做到「改對就留，改壞就退」。
其工作流程包括：
1.  **Evaluate (評估)**：執行測試題，計算 F1 分數來評估當前搜尋策略的效果。
2.  **Diagnose (診斷)**：分析失敗案例，找出搜尋失敗的原因。
3.  **Propose (提出)**：根據診斷結果，提出新的搜尋策略。
4.  **Guard (守護)**：如果新的策略效果提升（F1 分數上升），則採用；如果效果下降，則還原回舊策略。
這個過程會反覆迭代，直到不再進步。實驗結果顯示，透過 3 輪的自我演化，F1 分數能從 81.2% 提升到 100%。關鍵在於，演化改善的不是「找到更多資訊」，而是「排除會誤導模型的雜訊」，讓搜尋策略越來越精準。這就像一個越來越有經驗的客服主管，透過不斷嘗試、反思失敗案例、調整手冊，最終發展出更有效的應對策略。

## 結論
總結來說，在資源有限、無法進行 fine-tune 的現實情境下，僅僅依靠良好的記憶管理，就能讓 AI Agent 持續進化，這是一條可行且有效的路徑。Chain of Summaries 處理外部知識的壓縮，Recursively Summarizing 確保對話歷史的關鍵資訊得以保留，而 EvolveMem 則讓搜尋機制能夠自我診斷並持續優化。這三種方法可以疊加使用，且都屬於純 prompting 的輕量級架構，無需 fine-tune 即可實現 Agent 的強化。
