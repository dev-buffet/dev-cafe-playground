## JavaScript ES6+

此部分深入探討了現代 JavaScript (ES6+) 的關鍵特性，這些特性對於前端開發者而言是不可或缺的基礎。

### 變數宣告：var / let / const

JavaScript 提供了三種變數宣告方式，它們在作用域和可變性上有所不同：

*   **`var`**：具有函式作用域 (Function Scope)。`var` 宣告的變數可以在函式內部被存取，但其作用域會穿透區塊 (如 `if` 或 `for` 的大括號 `{}`)，容易污染全域環境，因此在現代 JavaScript 開發中已不推薦使用。
*   **`let`**：具有區塊作用域 (Block Scope)。`let` 宣告的變數僅在宣告所在的區塊內有效，可以在程式執行過程中重新賦值，常用於計數器或狀態變換等情境。
*   **`const`**：同樣具有區塊作用域，用於宣告常數，一旦賦值後就不能再重新指向新的記憶體位址。對於原始型別（如 string, number, boolean）而言，其值本身不可變；對於複合型別（如 Object, Array），`const` 鎖定的是記憶體位址，而非其內容，因此物件或陣列內部的屬性仍然可以修改。

總結來說，`var` 容易造成全域污染，`let` 提供了可變的區塊作用域變數，而 `const` 則提供唯讀的區塊作用域變數。

### 箭頭函式與 this

箭頭函式（Arrow Functions）提供了更簡潔的函式寫法，特別是對於只有單一表達式並需回傳值的函式，可以省略 `{} `與 `return` 關鍵字，實現隱式回傳。

其核心差異在於 `this` 的綁定機制：

*   **一般函式**：`this` 是「動態決定」的，它取決於函式被呼叫時的上下文。這使得在非同步操作（如 `setTimeout`）或 Callback 函式中，`this` 的指向容易變得混亂。例如，在 DOM 事件監聽器中，一般函式的 `this` 會指向觸發事件的 DOM 元素。
*   **箭頭函式**：`this` 是「靜態綁定」的，它在函式定義時就已確定，指向其外部作用域的 `this`。這使得箭頭函式在處理非同步程式碼或作為物件方法時，`this` 的行為更為直覺和可預期。例如，在 `setTimeout` 的 Callback 或物件方法中，箭頭函式的 `this` 會繼承其外部函式的 `this`，而非指向全域物件或 `undefined`。

因此，應根據對 `this` 綁定機制的掌握和需求，選擇使用不同型態的函式。

### 解構賦值 (Destructuring)

解構賦值允許我們從物件或陣列中解開資料，並將其擷取為獨立的變數，使程式碼更為簡潔。

*   **物件解構**：
    *   **基本解構**：將物件中的 `Key` 寫在大括號 `{}` 中，即可直接取得對應的值。
    *   **重新命名 (Alias)**：當不希望使用物件原有的 `Key` 名稱，或避免變數名稱衝突時，可以使用 `key: newName` 的語法重新命名。
    *   **設定預設值 (Default Value)**：當解構的 `Key` 沒有值（`undefined`）時，可使用 `=` 賦予預設值。
*   **陣列解構**：
    *   **基本解構 (按順序賦值)**：將陣列中的值依照索引位置，按順序賦予變數。
    *   **跳過特定位置 (忽略元素)**：使用逗號 `,` 留空，可以跳過不需要的陣列項目，直接取得目標位置的值。

在 React 元件開發中，解構賦值對於處理傳入的 `props` 物件尤為實用，它能讓參數傳遞更簡潔清楚，並能方便地帶入預設值。

### 展開與其餘運算子 (Spread & Rest Operators)

這兩個運算子都使用三個點 `...`，但根據使用情境有不同的功能：

*   **展開運算子 (Spread Operator)**：
    *   **用途**：像「解壓縮」一樣，將陣列或物件中的元素拆開，展開成個別獨立的值。
    *   **常見應用**：用於複製或合併陣列和物件，透過在新的陣列/物件內部展開舊資料，可以產生全新的記憶體位址，確保不破壞原始資料。在物件上，後方展開的屬性可以覆蓋前方同名的屬性。
    *   **位置**：通常用於等號右邊的「提供資料」或「傳入參數」處。

*   **其餘運算子 (Rest Operator)**：
    *   **用途**：用於「收集/打包」剩餘的屬性或元素，將其打包成一個獨立的物件或陣列。
    *   **常見應用**：在解構賦值時，當選取了需要使用的參數或屬性後，將剩下的部分收集起來。
    *   **位置**：通常用於等號左邊的「宣告變數」或「接收資料」處。

### 陣列方法：map / filter / reduce

JavaScript 提供了多種內建的陣列處理方法，它們的共同點是「不會直接修改原始陣列」，而是「產生新的陣列或累加結果」，這在 React 中對於觸發畫面更新尤其重要。

*   **`map()`**：
    *   **功能**：執行「一對一轉換」。將陣列中的每一個元素傳入指定函式處理後，回傳一個結構相同、但內容經過加工的新陣列。
    *   **應用**：常用於將資料陣列轉換成 JSX 元素陣列進行列表渲染。
*   **`filter()`**：
    *   **功能**：執行「過濾」。設定一個條件，檢查陣列中的每個元素，只保留符合條件（回傳 `true`）的元素，組成全新的陣列。
    *   **應用**：例如從待辦事項列表中篩選出未完成的項目。
*   **`reduce()`**：
    *   **功能**：執行「累加或凝聚」。將陣列中的每個元素依序傳入「累加器」函式進行計算，最終將整個陣列簡化為單一的數值或目標物件。
    *   **應用**：例如計算購物車中所有商品的總金額。

**React 畫面更新注意事項**：
React 在判斷是否重新渲染畫面時，會比對「資料的記憶體位址」是否改變。因此，若直接修改原陣列的方法（如 `push()`, `splice()`），將不會觸發畫面重新更新。為了確保畫面能正確響應資料變化，應使用 `map()`, `filter()`, `reduce()` 等會產生新陣列或新物件的方法來進行更新。

### 非同步處理：Asynchronous JS & Async/Await

前端開發經常會遇到需要等待時間的流程，例如向伺服器請求資料，這需要理解同步與非同步處理的差異。

*   **同步處理**：程式碼按照順序一行行執行，當遇到耗時操作時，會卡住等待其完成，才能繼續執行後續程式碼。
*   **非同步處理**：程式碼發出請求後不會卡在原地等待，而是繼續往下執行，等到耗時操作完成後再處理結果。JavaScript 使用 `Promise` 物件來追蹤這些「等待過程」。
    *   **Promise 的三種狀態**：
        *   **Pending (進行中)**：請求已送出，伺服器正在處理。
        *   **Fulfilled (已成功)**：成功拿到資料，回傳 Response。
        *   **Rejected (已失敗)**：網路中斷或 API 報錯。
*   **`async/await`**：是現代 JavaScript 用來撰寫非同步資料抓取邏輯的語法糖，讓非同步程式碼看起來更像同步程式碼，更易於閱讀和維護。
    *   當程式碼執行到 `await` 時，該非同步請求會進入 Pending 階段，程式會暫停等待回應。
    *   可搭配 `try/catch` 語句來處理潛在的錯誤，當 `try` 區塊有錯誤時，程式會直接進入 `catch` 區塊。
    *   `finally` 區塊則確保不論請求成功或失敗，其中的程式碼都會被執行，常用於執行收尾工作。

### ES Modules 模組化：Import & Export

ES Modules 是 JavaScript 原生的模組化機制，允許開發者將程式碼分割成獨立的檔案（模組），然後在需要時互相導入和導出，有助於提高程式碼的可維護性和重用性。

*   **具名導出 (Named Exports)**：
    *   **數量**：一個檔案可以有多個具名導出。
    *   **語法**：使用 `export const varName = value;` 或 `export function funcName() {}` 等。
    *   **引入**：引入時必須使用大括號 `{}`，且引入名稱必須與導出名稱完全一致。
    *   **範例**：`export const add = ...; import { add } from './math';`
*   **預設導出 (Default Export)**：
    *   **數量**：一個檔案只能有一個預設導出。
    *   **語法**：使用 `export default value;`。
    *   **引入**：引入時不需要使用大括號 `{} `，可以自由自訂變數名稱。
    *   **範例**：`export default Button; import CustomButton from './Button';`
    *   **特殊應用**：在 Next.js 等框架中，頁面 (`page.js`) 和全站排版 (`layout.js`) 必須使用預設導出。

## TypeScript

TypeScript 是 JavaScript 的靜態型別超集，它允許開發者在程式碼執行前的「編譯階段」進行型別檢查，提早發現潛在的邏輯與型別錯誤。透過明確標註型別，能有效減少開發中的 Bug，並大幅提升程式碼的可讀性與可維護性。

### 基礎與原始型別 (Primitives & Special Types)

TypeScript 提供了一系列基本的型別來定義變數，以及兩種特殊的通用型別。

*   **常用原始型別**：
    *   **`string`**：表示純文字，可以使用單引號、雙引號或反引號包覆。
    *   **`number`**：表示所有的數字，包含整數和浮點數。
    *   **`boolean`**：表示真假狀態，只有 `true` 和 `false` 兩種。
    *   **`null`**：表示明確設定為空的引用。
    *   **`undefined`**：表示變數已宣告但尚未賦值。
*   **特殊型別**：
    *   **`any`**：代表任何值。使用 `any` 會關閉 TypeScript 的型別檢查機制，雖然提供極大彈性，但也因此失去型別安全性，容易在運行時產生錯誤，故不建議使用。
    *   **`unknown`**：代表任何值，但比 `any` 更安全。在未進行型別檢測（或稱「型別收窄」）之前，不允許對 `unknown` 型別的變數執行任何操作。這意味著開發者必須先確認其具體型別，才能安全地使用，是最安全的通用容器。

### 複合型別與陣列 (Composite Types & Arrays)

除了原始型別，TypeScript 也支援定義更複雜的資料結構，如陣列和物件。

*   **陣列的型別**：
    *   **放同型別元素**：陣列包含多個相同型別的元素，長度可自由增減。可使用兩種寫法：
        *   **`T[]`** (後綴方括號寫法)：例如 `string[]` 或 `number[]`。
        *   **`Array<T>`** (泛型陣列寫法)：例如 `Array<string>`。
    *   **異質性容器 (元組 - Tuple)**：用於定義一個長度固定、每個位置對應特定型別的陣列。元組要求型別順序和長度都必須嚴格符合定義，否則會報錯。例如 `[string, number, boolean]`。
*   **物件的型別與必填選填**：
    *   物件型別的定義與元組類似，如果缺少定義的屬性或型別不符，都會導致編譯錯誤。
    *   **必填屬性**：直接定義屬性即可，該屬性在物件建立時必須提供。
    *   **選填屬性**：在屬性名稱後加上 `?` (問號)，表示該屬性是可選的，不一定要傳入。
    *   當物件結構變得複雜時，直接在行內定義型別會變得極難閱讀與維護。

### 介面 vs 型別別名 (Interface vs Type Alias)

為了解決複雜物件型別在行內定義導致的可讀性與維護性問題，TypeScript 提供了 `interface` 和 `type` 這兩種獨立定義型別的方式。

*   **`Interface` (介面)**：
    *   **用途**：主要用於定義物件的型別規格，通常用於定義一整個元件的屬性 (Props) 結構。
    *   **寫法**：直接使用物件大括號 `{}` 設定，不需使用等號 `=`。
    *   **擴充性**：可透過 `extends` 語法繼承其他介面，實現型別的複製與擴充。
    *   **命名慣例**：建議使用開頭大寫的駝峰式命名 (例如 `UserStyle`)。
*   **`Type Alias` (型別別名)**：
    *   **用途**：用來給任何型別取一個別名，包括原始型別、聯集型別 (`|`)、交集型別 (`&`) 等。
    *   **寫法**：使用等號 `=`，類似於變數宣告。
    *   **擴充性**：可透過 `&` (交集運算子) 將多個型別合併，達到類似繼承的效果。
    *   **聯集型別 (`|`)**：用於限制變數只能是多個指定型別中的其中一個，例如 `'sm' | 'md' | 'lg'`。

**使用時機的選擇**：
*   **模組化**：若型別（例如按鈕尺寸 `ButtonSize`）會被多個元件（如 `Card`, `Icon`）共用，則建議將其獨立定義為 `Type Alias`。
*   **行內內聯**：若某個型別只會用在單一元件內部，且不需在其他地方共用，則可以直接在元件的 `interface` 中行內定義。
總體而言，`Interface` 適合定義一整個物件的「規格」，而 `Type Alias` 則更適合定義個別項目或處理複雜的「型別組合」。

### 聯集型別 (Union Types)

聯集型別 `|` (Union Types) 允許我們將多個型別組合在一起，表示一個變數可以是這些型別中的任何一個。搭配「字面量型別 (Literal Types)」使用時，能夠指定變數只能是多個特定字串中的其中一個。

*   **應用場景**：
    *   **限制元件屬性**：常用於限制元件的屬性（如按鈕樣式 `primary | secondary | danger` 或尺寸 `sm | md | lg`），提供自動補全功能，並在開發時防止輸入無效值。
*   **可辨識聯集 (Discriminant Unions)**：
    *   當組合多種不同結構的物件型別時，若設計不當，容易產生「無效或矛盾的狀態」。
    *   透過在聯集的每個物件中加入一個共通的「可辨識標籤」（例如 `status: "success" | "error"`），TypeScript 就能在編譯時根據此標籤來區分不同的型別結構，進而避免矛盾狀態並提升型別安全性。例如，當 `status` 為 `"success"` 時，必須有 `data` 屬性；當 `status` 為 `"error"` 時，必須有 `errorMessage` 屬性。

### 泛型 (Generics)

泛型 (Generics) 允許我們在定義函式、介面或類別時，先「宣告一個型別輸入 `<T>`」，並將其對應到內部的資料欄位。在呼叫或使用時，再「傳入真正的型別」，即可動態生成精準的型別規格。

*   **目的**：解決重複撰寫相似程式碼的問題。例如，如果有多個 API 回應結構相似，但 `data` 欄位的型別不同，如果不使用泛型，就需要為每種 `data` 型別重複撰寫一個 `interface`。
*   **使用方式**：
    *   在定義介面或函式時，使用 `<T>` 作為型別參數的佔位符。
    *   在實際使用時，將具體的型別傳入 `<實際型別>`，TypeScript 會根據傳入的型別來推斷或生成最終的型別結構。

透過泛型，可以創建高度可重用且型別安全的元件或函式，避免程式碼冗長。

## React

React 是一個專門用於建構使用者介面的 JavaScript 函式庫。它與傳統 JavaScript 的「指令式」寫法不同，React 採用「宣告式」設計，開發者只需專注於資料狀態與畫面的對應關係，React 就會自動更新渲染畫面。

### 指令式 vs 宣告式

這兩種程式設計典範在 UI 開發中有著根本性的差異。

*   **指令式 (Imperative)**：
    *   **特點**：原生的 JavaScript 開發方式。開發者需要一步步手動選取（如 `getElementById`）、操作和修改每個 HTML 節點（DOM 元素）來更新 UI。
    *   **缺點**：當畫面變得龐大、資料互相關聯時，只要漏寫或寫錯其中一個步驟，畫面與資料就容易失去同步，導致維護困難。
*   **宣告式 (Declarative)**：
    *   **特點**：React 採用的設計模式，稱為「資料驅動畫面」。開發者只需定義好「資料狀態 (State)」與「UI 呈現」之間的對應關係，而無需關心「如何」抓取 DOM 或「步驟是什麼」。
    *   **優點**：當資料狀態改變時，React 會自動、高效地更新渲染畫面，確保畫面與資料始終保持同步。這大大簡化了 UI 的開發與維護。

### JSX 語法 (JavaScript XML)

JSX 是 React 提供的語法擴充，它允許開發者在 JavaScript 程式碼中直接撰寫類似 HTML 標籤的結構，用於直覺地定義 UI 介面。

*   **JSX 基本規則**：
    *   **單一根元素**：JSX 片段必須包含在一個單一的根元素中，或者使用空標籤 `<></>` 來包覆多個元素。
    *   **標籤自我閉合**：所有標籤都必須正確閉合，例如 `<img />` 或 `<br />`。
    *   **駝峰式命名屬性**：HTML 屬性在 JSX 中使用駝峰式命名（例如 `onClick` 而非 `onclick`），並避免使用 JavaScript 保留字（例如 `class` 改為 `className`）。
    *   **行內樣式為物件**：行內 CSS 樣式需要傳入一個 JavaScript 物件，例如 `style={{ backgroundColor: 'red', fontSize: '16px' }}`。
*   **JSX 語法解析**：
    *   瀏覽器無法直接識別 JSX。JSX 程式碼需要透過轉譯器（如 Babel 或 SWC）轉換為標準的 JavaScript 物件，這些物件代表了畫面的結構（稱為「虛擬 DOM」或 VDOM）。
    *   React 引擎會比對新舊虛擬 DOM 的差異，然後只更新實際發生變化的部分到「真實 DOM」上，從而實現高效的 UI 渲染，減少直接操作 DOM 的效能開銷。
*   **大括號插槽 `{}`**：
    *   在 JSX 結構中，大括號 `{}` 表示「切換回 JavaScript 模式」，可以在內部放入任何 JavaScript 變數或表達式，將動態資料注入到畫面上。
    *   **應用情境**：
        *   **基礎變數與運算式**：直接嵌入變數的值或進行簡單的運算。
        *   **自訂元件或 JSX**：將其他元件或 JSX 元素作為變數放入。
        *   **邏輯與 `&&` (條件顯示)**：當條件成立時顯示內容，不成立則不顯示。
        *   **三元運算子 `? :` (二選一顯示)**：根據條件決定顯示 A 或 B。
    *   **注意事項**：大括號內部只能放置「表達式」（即會回傳值的程式碼），不能直接放置「語句」（如 `if...else`、`for` 迴圈）。

### 元件與屬性傳遞 (Components & Props Architecture)

React 的核心概念是將 UI 拆解成獨立、可重用的「元件」(Components)，並透過「屬性」(Props) 在元件之間傳遞資料。

*   **元件 (Components)**：
    *   **定義**：React 元件本質上是一個接收輸入參數（Props）並回傳 JSX (UI) 的 JavaScript 函式。
    *   **命名慣例**：為了與標準 HTML 標籤區隔，元件名稱必須使用「大寫字母開頭」（例如 `UserCard`, `TodoItem`）。
    *   **好處**：元件化有助於管理介面、減少重複程式碼，提升程式碼的模組化和可維護性。
*   **Props (屬性)**：
    *   **用途**：作為元件的輸入參數，將資料從父元件傳遞到子元件。
    *   **單向傳遞**：資料流向是單向的，只能從父元件流向子元件。
    *   **唯讀限制**：子元件「絕對不能」在內部直接修改傳入的 Props，這確保了資料來源的清晰和可預測性。
    *   **修改方式**：若子元件需要改變資料，必須由父元件傳遞一個「觸發函式」作為 Props。子元件呼叫該函式，通知父元件進行資料更新。
    *   **整合 TypeScript**：可為 Props 定義型別介面 (`interface`)，明確指定必填屬性、選填屬性 (`?`) 和函式型別，並可設定預設值，提升型別安全與開發體驗。
*   **Children 容器模式**：
    *   **概念**：`children` 是 React 預留的關鍵字，允許一個元件像外殼一樣「包裹」其他 JSX 節點。被包裹的內容會自動作為 `props.children` 傳入。
    *   **好處**：這種模式讓元件更靈活、可重用，可以讓元件核心內容留白，允許使用者將任何表單、說明文字、圖片等內容塞入其中，形成容器型元件（例如 `Modal` 視窗元件）。

### 常用 Hooks (useState、useRef、useEffect)

Hooks 是 React 提供的特殊函式，允許函式元件「鉤入 (Hook into)」React 的底層核心機制，以使用狀態管理、外部系統同步或記憶體託管等能力。

*   **為什麼需要 Hooks？**
    在 React 中，直接修改函式元件內的一般區域變數不會觸發重新渲染 (Re-render)，且每次元件重新渲染時，區域變數都會被重置。Hooks 提供了一種機制，讓資料能夠「跨渲染週期」被保留，並能通知 React 畫面需要更新。
*   **`useState`**：狀態儲存空間
    *   **用途**：讓函式元件擁有保存狀態 (State) 的能力，並在狀態改變時觸發畫面重新渲染。
    *   **基本使用**：`const [value, setValue] = useState(initialValue);`。`value` 是當前狀態值，`setValue` 是更新狀態的專用函式。
    *   **內容不可變性**：當更新物件或陣列狀態時，必須建立一個「全新的」物件或陣列，而非直接修改原始狀態，因為 React 底層會使用 `Object.is()` 進行淺層比較，只有記憶體位址改變才會觸發重新渲染。
    *   **快照與函式型更新 (Functional Update)**：`useState` 的更新是批次處理的。若新的狀態值依賴於前一個狀態，應傳入一個 Callback 函式 `setValue(prev => prev + 1)`，以確保能拿到更新佇列中的最新值，避免吃到舊的狀態快照。
*   **`useRef`**：記憶體容器 / DOM 操作
    *   **用途**：讓函式元件能儲存「跨渲染週期的可變值」，且其改變時「不會」觸發畫面重新渲染。同時，它也是在 React 中直接存取和操作真實 DOM 元素的主要方式。
    *   **基本使用**：`const refContainer = useRef(initialValue);`。回傳一個包含 `current` 屬性的物件，可以直接修改 `refContainer.current`。
    *   **主要應用**：
        *   **操作真實 DOM 節點**：例如取得元素的尺寸、聚焦輸入框。
        *   **儲存不需觸發畫面更新的變數**：例如計時器 ID、前一次的狀態、或任何跨渲染週期但不需要即時顯示在 UI 上的資料。
*   **`useEffect`**：外部系統同步 / 副作用
    *   **用途**：讓函式元件能與「外部系統」保持同步的 Hook。它用於處理在 React 渲染機制之外的同步行為，這些行為被稱為「副作用 (Side Effects)」。例如：發送 API 請求、設定計時器、手動操作 DOM、註冊全域事件監聽。
    *   **結構**：`useEffect(() => { /* 副作用邏輯 */ return () => { /* 清理函式 */ }; }, [依賴陣列]);`
    *   **副作用邏輯 (Setup)**：在元件剛渲染完成後（元件被產生、進場），或依賴項改變時執行。
    *   **清理函式 (Cleanup, 可選)**：在元件被清除前（從畫面上移除），或在下一次副作用執行前執行。用於清理上一次副作用留下的資源（例如清除計時器、取消事件監聽）。
    *   **依賴陣列 (Dependencies Array)**：決定 `useEffect` 執行的觸發條件：
        *   **不寫依賴陣列**：每次渲染完成後都會執行 (監控全域變動，極少使用)。
        *   **空陣列 `[]`**：僅在「首次渲染進場」後執行一次（例如首次載入 API 資料、設定全域事件監聽器）。
        *   **有依賴項 `[a, b]`**：在首次渲染進場後，以及當 `a` 或 `b` 這些依賴項的值改變時執行（例如搜尋關鍵字改變時重新發送 API 請求）。

### 列表渲染 (Rendering Lists)

在 React 中，當需要渲染一連串結構相同但內容不同的元件清單時，通常會利用 JavaScript 原生的陣列 `map()` 方法，將資料陣列轉換成 JSX 元素陣列。

*   **步驟**：
    1.  **準備資料陣列**：通常是一個包含多個物件或值的陣列。
    2.  **呼叫 `map()` 方法**：對資料陣列呼叫 `map()`，並傳入一個 Callback 函式。
    3.  **Callback 函式**：這個函式會接收陣列中的每個項目 (`item`) 作為參數，並回傳要渲染的 JSX 內容（通常是一個子元件）。
    4.  **提供 `key` 屬性**：在 `map()` 渲染的每個 JSX 元素或元件上，必須提供一個「唯一且穩定」的 `key` 屬性。這個 `key` 幫助 React 辨識列表中哪些項目被改變、新增或移除，從而更高效地更新 DOM。通常使用資料項目中唯一的 ID 作為 `key`，避免使用陣列索引 (`index`) 作為 `key`，除非列表內容是靜態且永不變動。
