## Context

`strip-html-text-material` 讓 HTML 投影片在 PR 描述有網址時連到外部網址，並在同一行附註「原始檔：index.html」。實際看 202605 ZeroSpec 的 README 後，維護者認為附註會讓讀者以為 repo 檔是可讀版本，改為在連結下方放告知區塊（commit a155bd3）。本變更把這個做法通用化，寫進生成規則。

## Goals / Non-Goals

**Goals:**
- 讀者在 README 點到的投影片連結，優先是原作者提供的正確來源。
- repo 內素材不供閱讀或不完整時，README 明確告知，避免誤解投影片被不正確地部分引用。
- 告知文字格式固定，各場活動一致。

**Non-Goals:**
- 不自動判斷 PDF／PPTX 是否缺頁；「不完整」只依 PR 描述的明確註明。
- 不檢查外部網址是否可連線。
- 不回頭重新生成既有活動 README。

## Decisions

**D1. 連結目標優先序：PR 描述提供的投影片網址 > repo 內檔案。**
適用所有格式。原作者網址通常是最新、樣式完整的版本；repo 檔案是生成素材與備份。PR 描述沒有網址時才連 repo 檔，嚴禁編造網址（沿用既有限制）。

**D2. 素材分三類，決定附註方式：**

| 類型 | 判斷依據 | 有原始網址 | 無原始網址 |
|---|---|---|---|
| 不供閱讀 | 副檔名 `.html`（檔案標籤已標「HTML 投影片」） | 連網址＋告知區塊 A | 連 repo 檔＋告知區塊 B |
| 不完整 | PR 描述註明該檔為節錄、缺頁、僅供生成用 | 連網址＋告知區塊 A | 連 repo 檔＋告知區塊 B |
| 完整可讀 | 其他（PDF、PPTX、Markdown） | 連網址，同一行附註 `（repo 備份：<路徑>）` | 連 repo 檔（現行行為） |

**D3. 告知區塊用固定範本，放在基本資訊清單之後、`## 活動簡介` 之前。**
- A（有原始網址）：`> **關於本目錄的 \`<檔名>\`**：這份檔案是為了讓 AI 自動生成活動紀錄的管線讀取內容而放入 repo，<原因>。請以上方的原始投影片網址觀看完整內容。`
- B（無原始網址）：`> **關於本目錄的 \`<檔名>\`**：這份檔案是為了讓 AI 自動生成活動紀錄的管線讀取內容而放入 repo，<原因>。目前沒有提供原始投影片網址，內容可能不完整。`
- `<原因>`：HTML 為「並非供閱讀的版本——在 GitHub 上只會顯示原始碼，也缺少投影片所需的樣式與腳本，無法正確呈現」；不完整為「內容並不完整（<PR 描述中的說明>）」。
- 多份需要告知的檔案時，每份各一個區塊。
範本與 202605 手動加入的文字一致，讓新舊 README 呈現相同。

**D4. 規則寫在 prompt，不在程式端後處理。**
沿用 `strip-html-text-material` D5 的理由：連結與講者對應本來就由 prompt 控制，後處理需解析 README 結構，複雜度高。

**D5. 「不完整」只靠 PR 描述的明確註明。**
模型無法可靠判斷檔案是否缺頁；在 PR 模板引導講者註明（例如「slides.pdf 為節錄版」），模型據此判斷。沒有註明就視為完整。

## Risks / Trade-offs

- [模型未照範本輸出告知區塊，或漏掉] → 驗證時以測試 PR 實跑；README 可手動修正且不會被覆蓋。
- [講者忘了註明不完整] → 只能靠 PR 審查時補上；PR 模板註解提醒。
- [prompt 變長，規則互相干擾] → 規則集中在投影片連結一段，用表格式條列，避免散落。
