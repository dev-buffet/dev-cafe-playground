## Docker 入門 (測試講者)
本次分享由測試講者帶來 Docker 入門介紹，深入淺出地解釋了容器化技術的核心概念，並引導聽眾理解 Docker 如何幫助開發者實現應用程式的一致性部署與環境隔離。

### 什麼是容器
講者首先闡述了「容器」的核心概念。容器是一種輕量級、可攜式的軟體包裝技術，它將應用程式本身及其所有必要的相依套件（如函式庫、系統工具、程式碼和運行時）打包在一起。這種封裝方式確保了應用程式在任何運作環境中都能保持一致的行為，有效解決了因環境差異導致的部署問題，極大地提升了開發與運維的效率。

### Image 與 Container 的區別
接著，講者詳細解釋了 Docker 中兩個最核心且常被混淆的概念：「Image (映像檔)」和「Container (容器)」之間的明確區別與關係：
*   **Image**：Image 是一個唯讀的模板，包含了應用程式運行所需的一切配置、文件和程式碼。它就像是應用程式的一個藍圖、快照或靜態版本，一旦創建後便不再改變，確保了不同時間和環境下部署的一致性。
*   **Container**：Container 則是 Image 的一個可執行實例。當我們運行一個 Image 時，就會基於該 Image 創建一個或多個 Container。每個 Container 都是一個獨立、輕量級且隔離的運行環境，可以在其中執行應用程式，並且可以被啟動、停止、移動和刪除，而不會對主機系統或其他容器造成影響。

### Dockerfile 基本指令
在理解了 Image 和 Container 的基礎上，講者進一步介紹了如何透過 `Dockerfile` 來定義和建構自己的 Docker Image。Dockerfile 是一個簡單的文本文件，包含了一系列指令，用來自動化創建 Docker Image 的整個過程。講者重點介紹了以下幾個最常用且關鍵的基本指令：
*   `FROM`：用於指定基礎 Image，通常是一個作業系統（如 Ubuntu、Alpine）或包含特定運行時（如 Node.js、Python）的 Image。它是任何 Dockerfile 的第一條指令。
*   `RUN`：在 Image 建構過程中執行命令。這些命令通常用於安裝軟體、建立目錄、下載相依套件等，其結果會作為新的一層被保存到 Image 中。
*   `COPY`：將本地主機的文件或目錄複製到 Image 中的指定路徑。這通常用於將應用程式的原始碼或配置文件複製到 Image 內部。
*   `CMD`：指定容器啟動時要執行的預設指令。與 `RUN` 不同，`CMD` 的指令只會在容器運行時執行一次，並且一個 Dockerfile 中只能有一個 `CMD` 指令（若有多個，只有最後一個生效）。
